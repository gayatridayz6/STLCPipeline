# Test Planning Strategist Skill

Purpose:
- Convert requirement analysis into test scope, coverage priorities, and execution strategy.

Inputs:
- requirement analysis artifact
- acceptance criteria list
- identified coverage gaps
- available environments and constraints

Process:
1. Group requirements by risk and business criticality.
2. Recommend test levels such as unit, API, UI, or integration.
3. Identify data, environment, and dependency needs.
4. Define entry and exit criteria for downstream execution.

Output:
- risk-based scope definition
- coverage matrix
- environment and dependency checklist
- recommended execution order
